# 更好的题目集（Better PTA Problem Sets）

一个针对 [PTA（pintia.cn）](https://pintia.cn) 的浏览器扩展：在「活跃题目集」「所有题目集」列表页**按课程分组与筛选**，并给卡片加上课程徽章与截止倒计时，解决不同课程题目集混在一起、难以浏览的问题。

当前版本 **v0.9.3**：自动答题**可随时中止**——运行中「开始答题」按钮变身「中止答题」（红调），点击即停：在途 LLM/图片请求立刻断开、未开始的题目与题型不再作答、已填答案所在页照常保存（防「已填未存」被当作已答跳过），编程题跨页续跑也不会再翻向下一页。同时修掉「日志要等流程结束才现形」的问题：每题请求前实时记「请求模型中…」，LLM 请求 120 秒上限（服务瘫痪挂起不再吊死整个流程，超时报「已按超时中断」），编程题续跑的每题失败当场进日志、结束汇总带逐题失败明细，续跑进度环随题推进。

其余同 v0.9.2：答题状态胶囊升级为三态 `已完成` / `未完成` / `未答题`，并**顶替原生的 `已开放` 胶囊**——卡片状态一行从最多三个标签收敛到两个（`已开考` + 答题状态）。已开放但**还没进场**的题目集直接标 `未答题`（此前这类集合完全不显示状态：PTA 的考试场次在你首次进场时才创建，不在场次表里的必然零提交）。答题状态颜色随进度推进：未答题蓝 → 未完成橙 → 已完成绿。已知口径边界（按用户决定保持 v0.8.0 行为）：已作答只统计「提交待评测」的题目，判分后的题目（`PROBLEM_ACCEPTED` / `PROBLEM_WRONG_ANSWER`）不计入——纯判分题集会显示「未完成 0/N」，而 PTA 概览页按「有提交就算」显示 100%。

其余同 v0.9.1：设置弹窗**配置导入 / 导出**（JSON 文件，含各服务 API Key，导入经校验清洗、旧版导出自动迁移）；自动答题面板 **API Key 按服务各存一把**、**悬浮答题球可拖拽**（API Key 输入框改文本遮罩，浏览器的密码管理器不再误弹「要更新密码吗？」）。

其余同 v0.8.0：新增**答题进度**——取自考试概览页自己的接口，口径与 PTA 概览页一致；只对已开始且未关闭的考试型题目集取数，非考试型题目集 PTA 不提供进度。其余同 v0.7.2：工具栏弹窗全面重构（明暗双主题、开关化控件、「课程识别与高级规则」折叠、无障碍适配，页脚附 GitHub 仓库）；「题目关闭倒计时提醒」在弹窗中开启并填入自建后端地址与目标邮箱后，**打开 PTA 任意页面**即自动同步未关闭题目集到后端（不再限于「进行中」页），截止前（默认 3 天 / 1 天）发邮件提醒（同一时间到期的合并成一封汇总；测试邮件 60 秒冷却防连点）；页面增强同 v0.5.4（所有列表页默认 = PTA 原生列表 + 悬浮课程筛选条，区分课程开放状态——还有未关闭题目集的课程计数高亮（部分关闭显示 `开放/总数`），已全部关闭的课程灰显（选中时为深灰选中态）；分组视图与课程筛选经筛选条切换），并有「新标签页打开题目集」开关（默认开启，点卡片不再 SPA 同页跳转；Ctrl+Click 等修饰键行为不变）。含跨页聚合、同教师课程归并、答题进度，均在真实登录环境（69 条题目集）端到端验证。

## 安装与更新

1. `chrome://extensions`（Edge 为 `edge://extensions`）→ 开发者模式 →「加载已解压的扩展程序」→ 选 `extension/` 目录（构建产物已随仓库提交，克隆后无需先构建）。
2. **已装过旧版本**：在扩展卡片上点「刷新」（↻）后，重新打开题目集列表页。
3. 本地预览：浏览器直接打开 `preview.html`（mock 了数据与接口，实际运行 `core.js`，可验证聚合/筛选/折叠/模式切换）。

## 开发与构建

源码在 `src/`，用 [esbuild](https://esbuild.github.io/) 打包成单文件写回 `extension/` 的**原有路径**——`manifest.json`、`preview.html` 与发版流程因此都不用改，产物也提交进仓库，克隆后可直接加载。

```bash
npm install
npm run build     # 一次性构建（改完 src/ 必须跑一次）
npm run dev       # 监听源码变化自动重建
npm test          # node:test 单测：识别/归并/整组分页/时间文案/设置迁移/数据源记账/答题进度口径
```

- 改代码改 `src/` 下的文件；`extension/` 里的 `content/core.js`、`background.js`、`popup/popup.js` 是产物（首行有「构建产物」标记），不要直接编辑。
- CI（[check.yml](./.github/workflows/check.yml)）在每次推送/PR 跑单测并校验产物与源码一致，漂移会直接失败；发版流水线另有一道同样的校验。

## 发版流程（维护者）

推送 `v*` 形式的 tag 即自动发版（[.github/workflows/release.yml](./.github/workflows/release.yml)），无需手动打包：

1. 确认 `extension/manifest.json` 的 `version` 已改成本次版本号（与 tag 不一致时流水线直接报错退出）；
2. 打**附注 tag** 并推送：`git tag -a v0.8.0 -m "v0.8.0：一句话标题" -m "详细更新说明"` → `git push origin v0.8.0`；
3. Actions 自动把 `extension/` 打成 `better-pta-problems-v0.8.0.zip`（zip 内为一个目录，解压后可直接「加载已解压的扩展程序」）并发布 GitHub Release，**Release 标题/正文 = 附注 tag 的信息**。

tag 打错想重发：删远端 tag 后重打重推（`git push origin :refs/tags/v0.8.0`），或在 Actions 页用 workflow_dispatch 手动填 tag 重跑（Release 已存在时会失败，需先删 Release）。

## 题目关闭邮件提醒（可选，v0.6）

页面内的倒计时只是展示；想在截止前收到**邮件**提醒，需自建一个轻量后端（`server/` 目录）：

1. 部署后端：见 [server/README.md](./server/README.md)（systemd / Docker 现成配置，QQ/163 邮箱 SMTP 授权码教程在内；要求 Node ≥ 22.5，数据库用内置 `node:sqlite`，无需安装数据库）；
2. 插件弹窗 → 「题目关闭倒计时提醒」分类 → 打开「启用邮件提醒」→ 填服务器地址（`ip:port`，后端配置了令牌则写 `ip:port/令牌`）与目标邮箱 → 点「发送测试邮件」验证（60 秒冷却，防连点）；
3. 之后每次打开 PTA（任意页面，含 dashboard 与题目集详情页），未关闭题目集会自动同步到后端，截止前默认提前 3 天、1 天各收到一封邮件（时机由后端 `REMIND_BEFORE_MINUTES` 配置）；同一时间到期的多个题目集会合并成一封汇总邮件，不会连环轰炸。

只同步题目集的 id / 标题 / 教师 / 单位 / 截止时间，不含任何答题与学习行为数据；清空弹窗里的服务器地址或邮箱即完全关闭该功能。

## 自动答题（实验，v0.9）

用你自己的 LLM 账号，在题目列表页自动作答判断题 / 单选题 / 填空题（多空支持）与**编程题**（跨页逐题串行，每题真实提交一次）：

1. 插件弹窗 → 打开「自动答题面板」开关（实验功能默认关）；
2. 打开题目列表的任意题型页，右下角出现悬浮答题球，点开悬浮面板：面板分**「答题配置 / 模型配置」**两页（答题配置 = 语言、覆盖已作答、作答含图题、开始/中止答题与运行日志；模型配置 = 服务/端点/模型/API Key）。在「服务」里选择适配的模型——已适配 DeepSeek 官方 API（deepseek-flash 视觉）与 OpenCode Go 网关（默认模型 glm-5.3-flash 且可自填），也可选「自定义」填写任意 OpenAI 兼容端点 + 模型 id；**每个服务各存一份 API Key**（仅存本机浏览器，切换服务自动带出各自的 Key，互不覆盖；输入框用文本遮罩而非密码框，浏览器的密码管理器不会再误弹「要更新密码吗？」）、按需打开「覆盖已作答」；编程题多一行「语言（编程题）」——可跟随编辑器当前语言（默认）或固定为某一种（选项即本题集允许的语言白名单）。悬浮球可按住拖到页面任意位置（位置本机记住，球在任何角落面板都会自动朝空余一侧展开）；
3. 点「开始答题」：插件自动遍历该题集的全部题型页（判断 → 单选 → 填空 → 编程），客观题逐题把题干连同选项交给模型，把返回的字母 / TRUE / FALSE / 填空数组写入表单，每个题型页答完点一次 PTA 原生「保存」；**编程题**则转入逐题串行续跑：每题单独加载一个文档，把题面交给模型出码、写入该题草稿并让编辑器回带水合（校验语言与代码一致后才提交），逐题点「提交本题作答」真实评测。**运行中同一个按钮变为「中止答题」**，随时可叫停（含编程题续跑的任意一页）：在途请求立即断开、已落位的题目保持各自状态（已填答案所在页会保存）；LLM 请求设 120 秒上限，服务挂起不再吊住整个流程。进度显示在悬浮球的进度环与面板日志里（日志可清空，每题请求前后实时记录、失败当场报告），编程题跨页作答时日志随各页出现；
4. 已作答的题默认跳过（「覆盖已作答」开关重答全部）；题干/选项含图的题默认跳过并在日志报告——你用的是视觉模型时，可以打开「作答含图题」：插件会同你的登录态下载图片、编码后交给模型作答。

请求由页面自身上下文直连模型服务、不经过任何第三方服务器；模型回答质量由所选模型决定，作答是否正确需自行核对（答题中的题集 PTA 不提供对错反馈）。**纯文本模型看不见图片**——含图题要么跳过，要么切到视觉模型并开启「作答含图题」。**编程题提交即评测**：自动作答会实时生成提交记录与作答度，成绩由评测结果（代码正确性与运行时限）决定，与客观题的静默判分路径不同（面板底部有同样的固定说明）。该功能随「开始答题」按钮显式触发，平时不产生任何请求。

## 已知限制

- **PTA 改版**：接口路径、`.pc-list`、分页条类名（`paginationWrapper_*`）等若变化，表现为聚合退化为当前页分组或静默不注入，页面本身不受影响；控制台有警告。
- **聚合请求按路由记录**：PTA 标签切换是 SPA（同一文档），扩展把页面发出的列表请求按路径分别记录（v0.3.1 修复：此前取"全局最新请求"，快速切换标签"所有→活跃→没加载完就切回"会把活跃页的请求错当所有页的数据源，导致串页）。换页时筛选状态自动重置为全部。
- **聚合失败自动恢复**（v0.5.3）：切换路由会中止在途的旧聚合请求（不产生报错）；请求失败（网络抖动等）30 秒后自动重试，期间暂用上次聚合结果，从未成功过才退回当前页数据——插件视图可能短暂变少，页面本身不受影响。
- **排序语义**：组序 = 聚合数据（即用户在 PTA 选的排序）中各组首次出现的位置；组内保持该排序。
- **"已开考"徽章启发式**：关联考试 + 已开始 + （开放中或 7 天内关闭）时显示；极老考试集与 PTA 展示可能有细微出入。卡片自带 PTA 精确倒计时（"距离关闭还有…"）时不再叠加插件的倒计时。
- **答题进度的适用范围**（v0.8）：只对**考试型**（PTA 返回了 `examIdByProblemSetId` 关联）且**已开始、未关闭**的题目集显示——非考试型题目集 PTA 不提供进度接口（它自己的概览页也只显示"未答题/答题中"），已关闭的题目集不再取数（补做不了，也避免为几十个历史题目集逐个打接口）。进度按 2 分钟缓存，刚答完题切回列表页可能最多滞后 2 分钟。
- **暗色模式**：注入 UI 按浅色绘制（PTA 的暗色变量未适配）。
- **邮件提醒的同步时机**：打开 PTA 任意页面约 2 秒后自动推送一次；「进行中」页的聚合刷新可在会话中途捕获教师改期；配置变更即时推送。仅随「启用邮件提醒」开关生效（v0.7.1 起不再依赖「启用增强」，关掉页面增强也能收提醒）。
