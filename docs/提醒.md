# 题目关闭提醒（浏览器通知 / 邮件）

题目集临近关闭时提醒你。两条通道互相独立、任一开启即生效，默认档位都是**截止前 3 天、1 天各提醒一次**：

| 通道 | 配置成本 | 什么时候能响 |
|---|---|---|
| **浏览器通知**（默认开） | 零配置 | 浏览器在运行（前台后台都行） |
| **邮件提醒**（可选） | 需要自建一个轻量后端 + 一个邮箱 | 服务端 7×24 小时扫，浏览器没开也能收到 |

两条通道共用同一份数据与同一套「已完成的不再提醒」过滤；想彻底静默就把两个开关都关掉，插件不会外发也不会弹任何东西。

## 浏览器通知（默认开，零配置）

1. 弹窗 → 点「题目关闭倒计时提醒」（入口行右侧写着当前生效的通道）进入子页面 → 确认「浏览器通知」是开的（默认就是开的），点「发送测试通知」确认系统会弹出；
2. 之后打开 PTA（任意页面）时插件会把未关闭题目集同步一份到本机；截止前 3 天、1 天各弹一次系统通知；
3. 同一轮到点的多个题目集**合并成一条**通知（「N 个题目集即将关闭」，内容取最早关闭的那个），点通知或点按钮直接打开题目集——不会再连环弹一屏。

边界与注意事项：

- **只有浏览器在运行时才会响**。浏览器完全退出期间不会弹（这是本地通道的固有边界——要覆盖关机时段请用邮件通道）；重新打开浏览器后会补判一轮，**只要还没到截止时间，错过的档位会补上**，不会丢。
- **系统通知被关**（Windows 专注助手、系统设置里关掉浏览器通知）时通知不会弹出：弹窗入口行会红字提示「系统通知已关」，子页面里「浏览器通知」那一行同样有提示，点「发送测试通知」也能当场确认。
- 数据只留在本机：快照与「已提醒档位」去重表存在 `chrome.storage.local`（键 `bpsNotifyState`），**不产生任何网络请求**；已截止的条目 7 天清理、去重记录 90 天清理。
- 关掉开关即停止：开关关闭后不再把题目集写进本机存储，也不再弹通知。

## 邮件提醒（可选，v0.6）

想在浏览器没开、或换设备（手机邮箱）时也能收到，需要自建一个轻量后端（仓库里的 [`server/`](../server/README.md)）。

1. 部署后端：见 [server/README.md](../server/README.md)（systemd / Docker 现成配置，QQ/163 邮箱 SMTP 授权码教程在内；要求 Node ≥ 22.5，数据库用内置 `node:sqlite`，无需安装数据库）；
2. 插件弹窗 → 点「题目关闭倒计时提醒」进入子页面 → 打开「邮件提醒」→ 填服务器地址（`ip:port`，后端配置了令牌则写 `ip:port/令牌`）与目标邮箱 → 点「测试邮件」验证（60 秒冷却，防连点，冷却期间按钮上显示剩余秒数）；
3. 之后每次打开 PTA（任意页面，含 dashboard 与题目集详情页），未关闭题目集会自动同步到后端，截止前默认提前 3 天、1 天各收到一封邮件（具体档位由后端 `REMIND_BEFORE_MINUTES` 配置）；同一时间到期的多个题目集会合并成一封汇总邮件，不会连环轰炸。

邮件通道的两个字段**都填齐**（服务器地址 + 邮箱）才算开启；只填一半时按未开启处理，不会报错也不会外发。

## 提醒范围与开关

- **只同步题目集的 id / 标题 / 教师 / 单位 / 截止时间**，不含任何答题与学习行为数据。两个通道都关（或邮件半配置且浏览器通知关）时，插件完全不外发。
- **已完成的不再提醒**（v0.9.4 起的独立开关，默认开）：已答完的题目集两条通道都不再提醒。判定与卡片上的答题状态胶囊共用同一口径（v0.9.6 起为「有提交就算」，见[《核心结论》§2.1](./核心结论.md)）；进度取不到或非考试型题目集一律按未完成保留，宁可多提醒、不漏提醒。
- 非考试型题目集 PTA 不提供进度接口，无法判断是否做完，因此始终照常提醒。

同步时机（打开页面约 2 秒后推送一次、进行中页聚合刷新、配置变更即时推送）、节流规则、通知的档位判定与闹钟机制、后端扫描与合并逻辑、安全边界等实现细节，见[《核心结论》§6.1](./核心结论.md)。
