# 核心结论

> **一句话结论：完全可行，且已实装并在真实登录环境（69 条题目集）端到端验证。**
> 方案 = 内容脚本读取页面 DOM + 复用 PTA 自身的列表接口做跨页聚合；不逆向私有接口、不改写页面数据。

## 1. 结论依据总览

| 关键问题 | 结论 | 详情 |
|---|---|---|
| 数据从哪来 | 复用 PTA 自己的列表接口，不硬编码参数 | §2 |
| PTA 没有状态字段，卡片徽章怎么办 | 由时间字段 + 考试关联表推导，实测与原生展示一致 | §3 |
| PTA 是 React SPA，改了 DOM 会不会被冲掉 | MutationObserver + 签名比对 + 三层防御，已修过实际竞态 bug | §4 |
| 课程归属从哪来 | 标题命名约定 + 同教师相似归并，真实 69 条零未分类 | §5 |
| 安全边界 | 纯本地、仅列表页生效 | §6 |
| 有没有更简单的路 | 备选方案对比过，混合方案最优 | §7 |

## 2. 数据来源：复用 PTA 自身的列表接口

PTA 的「活跃题目集」「所有题目集」通过同一接口拉数据：

```
GET https://pintia.cn/api/problem-sets?filter=<F>&page=<N>&limit=<M>&order_by=<O>&asc=<A>
```

实测两条路由的差异只在 `filter`：

| 路由 | filter | 其他参数 |
|---|---|---|
| `/problem-sets/all` | `{}` | `limit=30, order_by=END_AT, asc=false` |
| `/problem-sets/active` | `{"endAtAfter":"<当前时刻 ISO>"}` | `limit=100, order_by=END_AT, asc=true` |

响应结构：

```json
{
  "total": 69,
  "problemSets": [{
    "id": "…", "name": "…", "timeType": "FIXED_TIME", "status": "PENDING",
    "startAt": "2026-09-20T14:15:00Z", "endAt": "2026-12-31T15:59:00Z",
    "ownerNickname": "教师B", "organizationName": "某高校", "stage": "NORMAL", "…": "…"
  }],
  "examIdByProblemSetId": { "<题目集id>": "<考试id>", "…": "…" },
  "homeworkByProblemSetId": {}
}
```

关键实测结论：

- **`limit=100` 服务端接受**，69 条一次拉全——跨页聚合只需 1 个请求；若日后被服务端封顶，代码里有按实际返回条数逐页拉取的兜底。
- **不硬编码请求参数**：扩展从 `performance.getEntriesByType('resource')` 里取**页面自己发出的**列表请求（含用户当前在 PTA 上设置的筛选/排序/排序方向），按路径记账后原样重放（仅改写 `page`/`limit`）。用户在 PTA 上改筛选，聚合自动跟随。
- **按路由记账而非取"全局最新"**：PTA 标签切换是 SPA（同一文档存活），快速切换"所有→活跃→没加载完就切回"时，全局最新的请求可能是另一页的——这曾导致"所有题目集页显示活跃内容"的真实 bug（v0.3.1 修复）。现在每个路径只消费属于自己的请求（水位线增量消费 resource timing）。
- **为什么不逆向更多私有接口**：列表场景所需字段（标题/起止时间/创建者/考试关联）已全部齐备；依赖越少，PTA 改版时破坏面越小。内容脚本与页面同源，带登录态 `fetch` 即可，无额外鉴权。

### 2.1 答题进度（v0.8，按需追加的一个接口）

列表接口本身**不含**答题进度，但 `examIdByProblemSetId` 就是取进度的钥匙：PTA 考试概览页（`/problem-sets/{id}/exam/overview`）的「答题进度」表来自

```
GET https://pintia.cn/api/exams/<examId>/problem-sets/<problemSetId>/problem-status
```

```json
{ "problemStatus": [
  { "id": "…", "problemType": "MULTIPLE_CHOICE", "problemSubmissionStatus": "PROBLEM_SUBMITTED", "score": 2 },
  { "id": "…", "problemType": "FILL_IN_THE_BLANK", "problemSubmissionStatus": "PROBLEM_NO_ANSWER",  "score": 10 }
], "examLabelByProblemSetProblemId": { "…": "2-1" } }
```

- **口径 = 「有提交就算」**（v0.9.6 起，与 PTA 概览页一致）：已作答 = 有提交/判分记录的题目数，总题数 = `problemStatus` 长度。实测 2-1 判断 5/5 + 单选 2/10 → 7/15，与概览页显示的 `47 %` 吻合；1-4 全对 12/12 对应页面 `100 %`。**判分后的状态不再是 `PROBLEM_SUBMITTED`**：编程题（含客观题判分后）变成 `PROBLEM_ACCEPTED` / `PROBLEM_WRONG_ANSWER` 等评测结论。v0.8～v0.9.5 只数 `PROBLEM_SUBMITTED`（当时视为"比概览页更严"的有意差异：实测作业1-1 编程 6 题 5 过 1 错，概览页 `100%` 而插件显示 `未完成 0/6`），2026-10-15 用户报障「实验1 全部答完仍标未完成」后改为按「排除没交」判定：**只有 `PROBLEM_NO_ANSWER`（以及字段缺失/空值）算未作答，其余非空状态（提交待判 / 判分结论 / 评测中 / 编译错误…）一律算已作答**——枚举正向词表会在 PTA 多出状态时重演「答完却显示未完成」，排除法不会。**状态枚举是闭集，已从 PTA 生产 bundle 复核（2026-10-15）**：`problemSubmissionStatus` 只有 4 个值 `PROBLEM_NO_ANSWER / PROBLEM_SUBMITTED / PROBLEM_ACCEPTED / PROBLEM_WRONG_ANSWER`（chunk 71629 的枚举定义），且 PTA 概览页统计每题型「已作答」用的就是排除法 `Number(status !== 'PROBLEM_NO_ANSWER')`（chunk 17539）——插件的判据与 PTA 逐字一致，不存在「评测中/编译错误」这类中间态。据此可证：**这次口径统一对「已完成的不再提醒」的过滤结果零影响**（v0.9.4 提醒侧的 `attempted` 白名单 = 枚举里除 `PROBLEM_NO_ANSWER` 外的三项，逐项重合；单测 `口径等价` 钉住），只有 PTA 将来新增状态时展示与提醒会一起把新状态当成「有提交」。bundle 取法：`https://pintia.cn/` 首页 → `main.<hash>.js` 里的 chunk 映射 → `https://static.pintia.cn/sparkling-daydream/<id>.<hash>.chunk.js`（无需登录）。展示胶囊与邮件提醒的「已完成」共用这一个计数。
- **`examIdByProblemSetId` 实为「考试场次表」（v0.9.2 修正）**：场次在用户首次进场时才创建——未进场题目集的 `/api/problem-sets/{id}/exams` 响应里连 `exam` 对象都没有、集合状态 `READY`，进场后变 `PROCESSING` 且响应多出 `exam`。提交必须挂在场次下，**不在表里的已开放题目集必然零提交**，插件直接标 `未答题`，不打接口（`problem-summaries` 对它们也是 403 `PERMISSION_DENIED`，本身就没有计数源；PTA 概览页对它们也只显示「答题信息：未答题」胶囊，没有进度表）。
- **必须带 `accept: application/json`**：缺这个头时接口返回二进制 protobuf（实测拿到的是乱码字节），内容脚本沿用 `fetchJson` 的请求头。
- **只对「已开始且未关闭」的题目集取数**：关闭后剩没剩题都无从补做；实测用户「所有题目集」里 69 条有 59 条是考试型，其中 53 条已关闭——逐个拉等于白刷 50 多个请求。请求并发 3、成功结果缓存 2 分钟、失败缓存 10 分钟，URL 带 `_bps=progress` 标记（路由记账跳过，不污染用户排序）。

## 3. 状态与徽章推导

接口的 `status` 字段**实测恒为 `PENDING`**（不可用），`timeType` 均为 `FIXED_TIME`。卡片状态徽章全部由时间与关联表推导：

| 条件 | 徽章（颜色） |
|---|---|
| `now < startAt` | 未开放（橙） |
| 已开始，未关闭 | 已开放（蓝）；若关联考试，另加 已开考（绿） |
| `now ≥ endAt` | 已关闭（灰）；关联考试且关闭未超 7 天的仍显示 已开考 |

"已开考"规则的反推依据：作业 01–06、08–11 与作业 07 的 `startAt` 完全相同，但仅 07 显示"已开考"；比对 `examIdByProblemSetId` 发现 07 与各课堂练习在列、其余作业不在——即**关联考试的题目集才开始后显示"已开考"**，与 PTA 原生展示完全吻合。

另外，PTA 部分卡片自带精确倒计时（"距离关闭还有…"），检测到时插件不再叠加自己的"剩 X 天"，避免重复。

## 4. SPA 环境下的稳定性设计

- PTA 是 React SPA，列表随筛选/翻页/路由重渲染；且**标签切换是 SPA 路由**（同一文档持续存活）。
- 插件的三层防御：
  1. **MutationObserver + 条目签名比对**：只在列表真正变化时重建插件视图；插件自身 DOM 全部收在 `.bps-root` 容器内，装卸干脆，不与 React 抢同一段 DOM。
  2. **聚合请求按路由记账**（见 §2）：配合换页时重置筛选状态，杜绝跨页状态污染。
  3. **重建签名包含当前 DOM 条目指纹**：即使聚合数据相同，换页后克隆卡片也强制刷新，防止旧页卡片滞留。
- 降级路径（都经过设计，失败不影响页面本身）：
  - 接口暂不可用 → 退回"当前页分组"（v0.1 行为），接口就绪后自动重建为全量聚合；
  - 聚合请求失败 → 30 秒退避后自动重试；已有聚合结果过期后继续暂用（可能略旧），从未成功过才退回当前页数据（v0.5.3）；
  - 切换路由时**中止**在途的旧聚合请求（AbortController），状态更新按路由 key 守卫——快速切换标签时旧请求的失败/晚到都不会污染新路由，也不会误报错误（v0.5.3）；
  - PTA 改版导致选择器/接口失效 → 静默不注入，页面照常工作，控制台有警告。
- 实测教训：合成 `el.click()` 会绕过 PTA 的路由拦截触发真实整页跳转，自动化测试必须用可信输入事件（CDP/CUA），否则会误判 PTA 是多页应用。

## 5. 课程识别管线（概要）

PTA 的数据里**没有**课程归属字段，课程信息只存在于标题命名约定中。识别按序回退：**自定义规则 > 分隔符 > 类型关键词 > 学年前缀兜底 > 同教师相似归并（教师粗分 + 最长公共子串）> 未分类**。

真实 69 条题目集验证结果：`算法设计与分析 7`、`代数结构与初等数论 11`、`数据结构 23`、`2024程序设计基础 13`、`2025 15`——零未分类、零碎片组。完整规则、阈值与示例见[《课程识别策略》](./课程识别策略.md)。

## 6. 安全与边界

- 内容脚本运行在浏览器隔离环境，全部逻辑本地执行，**默认不读取、不上报任何数据**；**浏览器通知通道（v0.10 起默认开）不产生任何网络请求**，数据只落本机 `chrome.storage.local`；唯一的外发通道是下述 v0.6 可选邮件提醒同步，且仅在开着邮件通道（开关 + 服务器地址 + 邮箱齐备）时才发生。
- 仅在列表路径（`/problem-sets`、`/problem-sets/active|all|finished|mine`）生效；题目集详情页、考试页完全不受影响。dashboard 页的"最近题目集"卡片是另一套 DOM 结构（`/exam` 链接、"将于…关闭"文案），选择器天然不命中——实测确认。

### 6.1 题目关闭提醒（浏览器通知 v0.10 / 邮件 v0.6）

两条通道互相独立、任一开启即工作；闸门判定（`reminderChannels`）是内容脚本与 background 的**同一份**实现，避免两侧漂移：浏览器通知＝开关开即生效（零配置），邮件＝开关开**且**服务器地址与邮箱齐备（半配置当未开启，不推送也不报错）。

**浏览器通知（v0.10，本地通道，纯本地、零配置）**：

- 内容脚本上报（`BPS_SYNC` 带 `browser: true`）→ background 把快照写 `chrome.storage.local`（键 `bpsNotifyState`：题目集快照 + 「题目集|档位」去重表 + 点击目标）→ `chrome.alarms` 每 30 分钟扫一轮（`bps-reminder-scan`）→ 到档位就 `chrome.notifications.create`，点击/按钮 `chrome.tabs.create` 打开题目集（打开后清掉该通知）；
- **档位判定不是精确触发**：`剩余 ≤ 档位（3 天 / 1 天）且该档未通知过`——闹钟会因浏览器没开、系统休眠而迟到甚至跨天，档位判定天然容忍迟到，关机期间错过的档位在下次扫描一并补发（通知里的剩余时间是现算的，不会出现「3 天前」这类陈旧文案）；同一次扫描命中的多个档位**一起记账**，避免补发时连环弹；多条并成一条汇总通知（取最早关闭的那条），固定通知 id 让新一轮替换旧一条、不在系统通知里堆积；
- 闹钟只按「缺则建」（`alarms.create` 会重置下一次触发时刻，每次 SW 启动都 create 会把周期无限推后），且不依赖闹钟跨浏览器重启保留：每次 SW 启动 + `onStartup`/`onInstalled` 都补建闹钟并补一轮扫描——**实测（Edge 149 无头 + 未打包扩展 + CDP 驱动）**：SW 空闲被回收后闹钟到点能把它唤醒（SW 启动计数 1→2、触发记录落在预定时刻、下一轮自动排到 +2 分钟），`periodInMinutes` 0.5 → 精确 30000 ms、0.1 → 6000 ms 且每 6 秒真实触发；浏览器进程完全退出期间的到点**不补发**（这是本地通道的固有边界，重新打开浏览器后由补判兜住）；
- 通知文案刻意只留一行（Windows 正文 2~3 行截断）：单条「《标题》约 X 天后关闭」+ 截止时间，多条「N 个题目集即将关闭 + 最早那条」；只用 `basic` 类型 + 1 个按钮（`list`/`progress` 有平台限制，按钮数各平台上限 2）；
- 系统级通知被关（专注助手 / 系统设置）时 `getPermissionLevel()` 返回 `denied`：扫描跳过且不记账（下一轮再试），弹窗在入口行与子页面的开关行都提示「系统通知已关」，测试通知会如实报错；
- 状态裁剪与服务端同口径：去重表留 90 天（对齐 `sent_log`）、已截止快照留 7 天（对齐订阅清理）；弹窗高度实测（v0.11.0 的四页结构）：主页面 472px、提醒 546px、规则 345px、备份 273px（600px 上限内；原「折叠区」结构为展开 597px / 收起 503px）。
- **弹窗设计令牌来自 PTA 实抓（2026-10-16）**，不是凭印象配的：登录态 `problem-sets/dashboard` 与 `problem-sets/active` 的 `:root` / `.dark` 与 `.pc-button`、输入框、头像菜单浮层的真实 CSS 里，交互主色是 `--color-primary: hsl(212, 89%, 53%)`（#1C80F2）——**#0a4991 是品牌深蓝 `--color-pta`，PTA 只把它用在输入框聚焦环 `rgba(10,73,145,.25)` 上**；正文灰阶是中性 `#404040 / #737373 / #999999`，输入框边框是字面量 `#ced4da`，暗色由 `.dark` 类切换（页面 #333 / 卡片 #404040 / 主色 `hsl(212,100%,60%)`，弹窗取它的值跟随 `prefers-color-scheme`）。令牌落在 `extension/popup/popup.html` 的 `:root` 并注明来源，**改色/圆角/时长前回 PTA 页面复核**；注入列表页样式（`--bps-*`）与悬浮面板用的是同一套值的**手写拷贝**（PTA 不对外提供可引用的样式表），三份是否还一致由 `test/injected-theme.test.js` 按语义角色逐项钉住（亮暗各一遍）。
- **注入 UI 与悬浮面板跟随 PTA 的主题类，不跟随系统**（2026-10-16 实测）：PTA 的暗色类**挂在 `<body>` 上而不是 `<html>`**（试主题时 `document.documentElement.classList` 一直为空，`document.body.className === 'dark'`），所以注入样式一律写 `.dark xxx`、面板的 `syncTheme()` 同时读 body/html 两处并镜像到 Shadow host（`MutationObserver` 观察两处 class）。弹窗是独立窗口、读不到页面主题类，仍跟 `prefers-color-scheme`——两者机制不同是有意的。
- 悬浮面板的按钮/输入框/页签按 PTA 的实件抄：实心按钮 hover `brightness(.85)`、按下 `translateY(1px)`；页签是 PTA 的 2px 下划线式（非胶囊式）；输入框 32px 高 / 4px 圆角 / `#ced4da` 边框 / 聚焦「主色边框 + 2px 环」；状态胶囊 = 12px 圆角 + 色值 10% 底 + 同色文字。**分区是可滚动的 flex 列，子项必须 `flex: none`**——不写这条时定高的主按钮被压成 24.5px（32px 设计值），实测抓到并修。

**邮件（v0.6，可选，需自建后端）**：

- 仅当弹窗「邮件提醒」开关打开（v0.6.2 起，关闭即暂停且保留配置）且**同时填写**「服务器地址」与「目标邮箱」后才生效，清空或关闭即关闭；v0.7.1 起不再依赖「启用增强」总开关——关闭页面增强也能收提醒；v0.10 的 v7 迁移把旧的「启用邮件提醒」开关（`reminderEnabled`）更名为 `reminderEmailEnabled`，状态原样跟随；
- 两条触发路径，payload 同构（未关闭题目集的 `id / 标题 / 教师 / 单位 / 截止时间`，经 background service worker POST 到自建后端；**不含任何作答与学习行为数据**；后端配置了 `TOKEN` 时以 `X-Token` 头透传，插件服务器地址写作 `ip:port/令牌`）：
  1. **打开 PTA 任意页面**（含 dashboard/详情页）约 2 秒后，直连拉取一次「进行中」全集再推送——防止只有打开「进行中」列表页才同步造成漏提醒。查询参数取 §2 实测结论（`endAtAfter` 过滤 + `END_AT` 升序 + `limit=100`）；此处属后台数据同步而非页面功能，允许硬编码，页面功能仍坚持重放页面自身请求；请求带 `_bps` 标记，路由记账跳过，防止插件流量污染页面请求记账（否则会覆盖用户在 PTA 上选的排序）。
  2. **「进行中」页聚合成功后的新鲜度钩子**（仅该路由——其余路由的聚合是筛选子集，全量替换语义下推子集会丢数据），捕获会话中途教师改期等 `endAt` 变化。
  这两条路径同时服务两条通道：一次上报里带 `browser`/`server`/`email` 三个通道标记，background 按标记分发（本地落盘 / POST 后端 / 两者都做）。
- 同步节流：每次页面加载强制同步一次；同文档内配置未变的直连重拉 ≥ 5 分钟；聚合路径签名未变 30 分钟内静默；变更任何提醒通道配置（开浏览器通知、换邮箱等）立即强制同步；
- 后端（`server/`，Node ≥ 22.5 + node:sqlite + Express + Nodemailer）按邮箱事务性全量替换订阅，每分钟扫描，截止前 `REMIND_BEFORE_MINUTES`（默认 3 天 / 1 天）各发一封邮件；同一轮检查中同邮箱同档位到期的多条提醒**合并为一封汇总邮件**（多门课同一时间截止时不再连环发信，错峰截止各自触发），已发记录去重、宕机补发受宽限约束；部署见 `server/README.md`；
- **邮件通道不加 host_permissions**：background 的跨源 fetch 走标准 CORS，由后端返回 `Access-Control-Allow-Origin: *` 放行；v0.10 起权限面为 `storage, alarms, notifications`（`alarms`/`notifications` 只服务本地通道，均无 host 权限）；
- 提醒不再依赖「启用增强」（v0.7.1 起，直连同步独立于页面增强的聚合）；「进行中」页的新鲜度钩子仍只在聚合运行时有意义。
- 「发送测试邮件」防连点：插件侧 60s 冷却（起点存 `chrome.storage.session`，重开弹窗不绕过）+ 后端 `/api/test` 每邮箱冷却（`TEST_COOLDOWN_SECONDS`，默认 60s，超频 429）双保险；「发送测试通知」是本地动作，用固定通知 id 替换旧的一条，不需要冷却。
- **已完成的不再提醒**（v0.9.4，默认开独立开关）：两条推送路径在构建 payload 前先把答题窗口内条目的进度拉齐（与列表胶囊共用 progress.js 的缓存与取数管线，答题进度开关关闭时也照常取数），剔除「每道题都有提交/判分记录」的条目——**对邮件是订阅全量替换语义、对本地是快照全量替换语义，剔除即两条通道都不再提醒**；之后做完了，下一次同步自然重新纳入（已发过的档位由各自去重表兜住，不会重发）。**「已完成」判定与展示胶囊共用同一个计数**（v0.9.6 起统一到 §2.1 的「有提交就算」；v0.9.4 时提醒侧曾单独用宽松口径 `attempted`，因为当时的展示口径只数 `PROBLEM_SUBMITTED`，判分完的题集在提醒侧会永远算未完成）。两条边界按 fail-open 处理：进度缺失（未取到/失败/过期）或非考试型（无考试场次、无计数源）一律按未完成保留，仍会提醒；做完全部题但再没打开过 PTA，旧订阅/旧快照仍在，最后一档提醒照发——同步只发生在打开 PTA 之后。服务端零改动、协议仅在 payload 上增加通道标记。

## 7. 备选方案对比

| 方案 | 评估 | 结论 |
|---|---|---|
| 纯 DOM 改写（v0.1 做法） | 可行，但列表数据只覆盖当前页——筛选条翻页不稳定，跨页课程数量无法统计 | 已淘汰 |
| 完全自绘 UI（接管整个列表） | 卡片渲染脱离 PTA 样式体系（含暗色模式），改版维护成本最高 | 弃 |
| **混合（现状）**：聚合接口数据定内容 + DOM 克隆定外观 | 当前页克隆 PTA 原生卡片（保真、暗色/悬停随 PTA），其余页按接口重建卡片（复用 PTA 样式类）；数据全量、视觉一致 | ✓ 采用 |
| 纯读取接口、完全不看 DOM | 对 PTA 客户端改版最敏感，且丢失"用户当前筛选"上下文，需自行硬编码路由语义 | 弃 |

## 8. 风险与缓解

| 风险 | 表现 | 缓解 |
|---|---|---|
| 接口路径/参数变更 | 聚合失效 | 静默退化为当前页分组 + 控制台警告；接口封装集中在少数函数 |
| DOM 选择器变更（`.pc-list`、`div[title]`、`paginationWrapper_*` 等） | 不注入/部分功能缺失 | 选择器集中在解析函数内；失效时页面照常工作 |
| resource timing 缓冲被冲掉 | 找不到页面自身的请求 | 初始化时扩容缓冲区至 1000；找不到则降级并在后续 sync 重试 |
| "已开考"启发式与 PTA 有出入 | 个别老考试集徽章差异 | 只影响装饰性徽章，不影响分组与数据 |
| 服务端将来封顶 `limit` | 聚合需多次请求 | 已内置按实际返回条数逐页拉取的兜底 |
