# 核心结论

> **一句话结论：完全可行，且已实装并在真实登录环境（69 条题目集）端到端验证。**
> 方案 = 内容脚本读取页面 DOM + 复用 PTA 自身的列表接口做跨页聚合；不逆向私有接口、不改写页面数据、不触碰答题页。

## 1. 结论依据总览

| 关键问题 | 结论 | 详情 |
|---|---|---|
| 数据从哪来 | 复用 PTA 自己的列表接口，不硬编码参数 | §2 |
| PTA 没有状态字段，卡片徽章怎么办 | 由时间字段 + 考试关联表推导，实测与原生展示一致 | §3 |
| PTA 是 React SPA，改了 DOM 会不会被冲掉 | MutationObserver + 签名比对 + 三层防御，已修过实际竞态 bug | §4 |
| 课程归属从哪来 | 标题命名约定 + 同教师相似归并，真实 69 条零未分类 | §5 |
| 安全边界 | 纯本地、仅列表页生效、不碰答题 | §6 |
| 有没有更简单的路 | 备选方案对比过，混合方案最优 | §7 |

## 2. 数据来源：复用 PTA 自身的列表接口

PTA 的「活跃题目集」「所有题目集」通过同一接口拉数据：

```
GET https://pintia.cn/api/problem-sets?filter=<F>&page=<N>&limit=<M>&order_by=<O>&asc=<A>
```

实测两条路由的差异只在 `filter`：

| 路由 | filter | 其他参数 |
|---|---|---|
| `/problem-sets/all` | `{}` | `limit=30, order_by=END_AT, asc=false` |
| `/problem-sets/active` | `{"endAtAfter":"<当前时刻 ISO>"}` | `limit=100, order_by=END_AT, asc=true` |

响应结构：

```json
{
  "total": 69,
  "problemSets": [{
    "id": "…", "name": "…", "timeType": "FIXED_TIME", "status": "PENDING",
    "startAt": "2026-09-20T14:15:00Z", "endAt": "2026-12-31T15:59:00Z",
    "ownerNickname": "教师B", "organizationName": "某高校", "stage": "NORMAL", "…": "…"
  }],
  "examIdByProblemSetId": { "<题目集id>": "<考试id>", "…": "…" },
  "homeworkByProblemSetId": {}
}
```

关键实测结论：

- **`limit=100` 服务端接受**，69 条一次拉全——跨页聚合只需 1 个请求；若日后被服务端封顶，代码里有按实际返回条数逐页拉取的兜底。
- **不硬编码请求参数**：扩展从 `performance.getEntriesByType('resource')` 里取**页面自己发出的**列表请求（含用户当前在 PTA 上设置的筛选/排序/排序方向），按路径记账后原样重放（仅改写 `page`/`limit`）。用户在 PTA 上改筛选，聚合自动跟随。
- **按路由记账而非取"全局最新"**：PTA 标签切换是 SPA（同一文档存活），快速切换"所有→活跃→没加载完就切回"时，全局最新的请求可能是另一页的——这曾导致"所有题目集页显示活跃内容"的真实 bug（v0.3.1 修复）。现在每个路径只消费属于自己的请求（水位线增量消费 resource timing）。
- **为什么不逆向更多私有接口**：列表场景所需字段（标题/起止时间/创建者/考试关联）已全部齐备；依赖越少，PTA 改版时破坏面越小。内容脚本与页面同源，带登录态 `fetch` 即可，无额外鉴权。

## 3. 状态与徽章推导

接口的 `status` 字段**实测恒为 `PENDING`**（不可用），`timeType` 均为 `FIXED_TIME`。卡片状态徽章全部由时间与关联表推导：

| 条件 | 徽章（颜色） |
|---|---|
| `now < startAt` | 未开放（橙） |
| 已开始，未关闭 | 已开放（蓝）；若关联考试，另加 已开考（绿） |
| `now ≥ endAt` | 已关闭（灰）；关联考试且关闭未超 7 天的仍显示 已开考 |

"已开考"规则的反推依据：作业 01–06、08–11 与作业 07 的 `startAt` 完全相同，但仅 07 显示"已开考"；比对 `examIdByProblemSetId` 发现 07 与各课堂练习在列、其余作业不在——即**关联考试的题目集才开始后显示"已开考"**，与 PTA 原生展示完全吻合。

另外，PTA 部分卡片自带精确倒计时（"距离关闭还有…"），检测到时插件不再叠加自己的"剩 X 天"，避免重复。

## 4. SPA 环境下的稳定性设计

- PTA 是 React SPA，列表随筛选/翻页/路由重渲染；且**标签切换是 SPA 路由**（同一文档持续存活）。
- 插件的三层防御：
  1. **MutationObserver + 条目签名比对**：只在列表真正变化时重建插件视图；插件自身 DOM 全部收在 `.bps-root` 容器内，装卸干脆，不与 React 抢同一段 DOM。
  2. **聚合请求按路由记账**（见 §2）：配合换页时重置筛选状态，杜绝跨页状态污染。
  3. **重建签名包含当前 DOM 条目指纹**：即使聚合数据相同，换页后克隆卡片也强制刷新，防止旧页卡片滞留。
- 降级路径（都经过设计，失败不影响页面本身）：
  - 接口暂不可用 → 退回"当前页分组"（v0.1 行为），接口就绪后自动重建为全量聚合；
  - 聚合请求失败 → 30 秒退避后自动重试；已有聚合结果过期后继续暂用（可能略旧），从未成功过才退回当前页数据（v0.5.3）；
  - 切换路由时**中止**在途的旧聚合请求（AbortController），状态更新按路由 key 守卫——快速切换标签时旧请求的失败/晚到都不会污染新路由，也不会误报错误（v0.5.3）；
  - PTA 改版导致选择器/接口失效 → 静默不注入，页面照常工作，控制台有警告。
- 实测教训：合成 `el.click()` 会绕过 PTA 的路由拦截触发真实整页跳转，自动化测试必须用可信输入事件（CDP/CUA），否则会误判 PTA 是多页应用。

## 5. 课程识别管线（概要）

PTA 的数据里**没有**课程归属字段，课程信息只存在于标题命名约定中。识别按序回退：**自定义规则 > 分隔符 > 类型关键词 > 学年前缀兜底 > 同教师相似归并（教师粗分 + 最长公共子串）> 未分类**。

真实 69 条题目集验证结果：`算法设计与分析 7`、`代数结构与初等数论 11`、`数据结构 23`、`2024程序设计基础 13`、`2025 15`——零未分类、零碎片组。完整规则、阈值与示例见[《课程识别策略》](./课程识别策略.md)。

## 6. 安全与边界

- 内容脚本运行在浏览器隔离环境，全部逻辑本地执行，**默认不读取、不上报任何数据**；唯一的外发通道是下述 v0.6 可选的邮件提醒同步。
- 仅在列表路径（`/problem-sets`、`/problem-sets/active|all|finished|mine`）生效；题目集详情页、考试页完全不受影响。dashboard 页的"最近题目集"卡片是另一套 DOM 结构（`/exam` 链接、"将于…关闭"文案），选择器天然不命中——实测确认。
- 产品定位是**浏览增强**：自动作答 graded 作业/考试属于学术诚信问题，本项目不做。

### 6.1 题目关闭邮件提醒（v0.6，可选）

- 仅当用户在弹窗中**同时填写**「服务器地址」与「目标邮箱」后才生效，清空即完全关闭；
- 打开「进行中」页聚合成功后（该路由的聚合结果是未关闭题目集的全集，其余路由是筛选子集——按邮箱全量替换语义下推子集会丢数据），把未关闭题目集的 `id / 标题 / 教师 / 单位 / 截止时间` 经 background service worker POST 到自建后端；**不含任何作答与学习行为数据**；后端配置了 `TOKEN` 时以 `X-Token` 头透传（插件服务器地址写作 `ip:port/令牌`）；
- 同步节流：payload 签名未变且 30 分钟内不重发（endAt 不变即静默）；刚保存提醒配置时立即同步一次；
- 后端（`server/`，Node ≥ 22.5 + node:sqlite + Express + Nodemailer）按邮箱事务性全量替换订阅，每分钟扫描，截止前 `REMIND_BEFORE_MINUTES`（默认 3 天 / 1 天）各发一封邮件；同一轮检查中同邮箱同档位到期的多条提醒**合并为一封汇总邮件**（多门课同一时间截止时不再连环发信，错峰截止各自触发），已发记录去重、宕机补发受宽限约束；部署见 `server/README.md`；
- **不加 host_permissions**：background 的跨源 fetch 走标准 CORS，由后端返回 `Access-Control-Allow-Origin: *` 放行，扩展权限面不变（仍只有 storage）；
- 提醒随「启用增强」总开关生效（聚合只在开关开启时运行）。

## 7. 备选方案对比

| 方案 | 评估 | 结论 |
|---|---|---|
| 纯 DOM 改写（v0.1 做法） | 可行，但列表数据只覆盖当前页——筛选条翻页不稳定，跨页课程数量无法统计 | 已淘汰 |
| 完全自绘 UI（接管整个列表） | 卡片渲染脱离 PTA 样式体系（含暗色模式），改版维护成本最高 | 弃 |
| **混合（现状）**：聚合接口数据定内容 + DOM 克隆定外观 | 当前页克隆 PTA 原生卡片（保真、暗色/悬停随 PTA），其余页按接口重建卡片（复用 PTA 样式类）；数据全量、视觉一致 | ✓ 采用 |
| 纯读取接口、完全不看 DOM | 对 PTA 客户端改版最敏感，且丢失"用户当前筛选"上下文，需自行硬编码路由语义 | 弃 |

## 8. 风险与缓解

| 风险 | 表现 | 缓解 |
|---|---|---|
| 接口路径/参数变更 | 聚合失效 | 静默退化为当前页分组 + 控制台警告；接口封装集中在少数函数 |
| DOM 选择器变更（`.pc-list`、`div[title]`、`paginationWrapper_*` 等） | 不注入/部分功能缺失 | 选择器集中在解析函数内；失效时页面照常工作 |
| resource timing 缓冲被冲掉 | 找不到页面自身的请求 | 初始化时扩容缓冲区至 1000；找不到则降级并在后续 sync 重试 |
| "已开考"启发式与 PTA 有出入 | 个别老考试集徽章差异 | 只影响装饰性徽章，不影响分组与数据 |
| 服务端将来封顶 `limit` | 聚合需多次请求 | 已内置按实际返回条数逐页拉取的兜底 |
