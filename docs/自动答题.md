# 自动答题（实验，v0.9）

用你自己的 LLM 账号，在题目列表页自动作答判断题 / 单选题 / 填空题（多空支持）与**编程题 / 函数题**（编码题批量模式：一次性收题 → 并发请求模型 → 逐题真实提交）。实验功能默认关闭，随「开始答题」按钮显式触发，平时不产生任何请求。

## 使用步骤

1. 插件弹窗 → 打开「自动答题面板」开关（实验功能默认关）；
2. 打开题目列表的任意题型页，右下角出现悬浮答题球，点开悬浮面板。面板分**「答题配置 / 模型配置」**两页：

   - 答题配置 = 语言（编程题）、并发数（编码题）、已答题处理、作答含图题、开始/中止答题与运行日志；
   - 模型配置 = 服务 / 端点 / 模型 / API Key。在「服务」里选择适配的模型——已适配 DeepSeek 官方 API（deepseek-flash 视觉）与 OpenCode Go 网关（官方基址 `https://opencode.ai/inference/go/openai/v1`，默认模型 glm-5.3-flash 且可自填，仅 chat 系模型可用），也可选「自定义」填写任意 OpenAI 兼容端点 + 模型 id。OpenCode Go 只支持走 `/chat/completions` 的模型系（GLM / Kimi / DeepSeek / LongCat / MiMo 等）；Claude、GPT/Grok、Gemini 等走别的协议，填了会在开跑前直接报错，不会白耗请求。

   **每个服务各存一份 API Key**（仅存本机浏览器，切换服务自动带出各自的 Key，互不覆盖；输入框用文本遮罩而非密码框，浏览器的密码管理器不会再误弹「要更新密码吗？」）。按需选择「已答题处理」——**跳过已答**（默认，保留原有答案）、**仅重做错误题**（编码题按 PTA 判分状态只重做未通过的题；编辑器里有草稿但从未提交的题也会重做；已通过的题不再请求模型）、**全部重做**（覆盖所有已答题，消耗更多 token）。「仅重做错误」只作用于编码题：客观题答题中不判分，仍按跳过处理；判分状态接口读不到时保守按「跳过已答」处理，不会批量覆盖。编程题多一行「语言（编程题）」——可跟随编辑器当前语言（默认）或固定为某一种（选项即本题集允许的语言白名单）；函数题的编译器由题目固定，该配置对函数题不生效。「并发数（编码题）」是同时向模型发起的请求数（1–6，默认 3）——只加速「等模型出码」这一段，收题与提交仍是串行页面操作；实测 OpenCode Go 6 路无 429，慢模型或限流严格的服务建议 1–3。悬浮球可按住拖到页面任意位置（位置本机记住，球在任何角落面板都会自动朝空余一侧展开）；
3. 点「开始答题」：插件自动遍历该题集的全部题型页（判断 → 单选 → 填空 → 编程/函数），客观题逐题把题干连同选项交给模型，把返回的字母 / TRUE / FALSE / 填空数组写入表单，每个题型页答完点一次 PTA 原生「保存」；**编码题（编程题 / 函数题）**则转入**批量模式**，分三个阶段：
   - **收题**：在题型页内用 SPA 切题逐个读题面（不整页装载，每题约 2 秒），记录题干、语言与已答状态；
   - **并发作答**：回到题目列表页，按「并发数」同时向模型发起请求（按「已答题处理」：默认跳过已答；仅重做错误时只请求判分未通过的题），出码后按平台限流口径逐题写入草稿；
   - **逐题提交**：回到每道题的页面，让编辑器回带代码（校验语言与代码一致），点「提交本题作答」真实评测。

   函数题（PTA 协议名 CODE_COMPLETION，侧栏叫「函数题」）只让模型产出**要嵌进「裁判测试程序样例」模板的函数实现**——签名与「函数接口定义」完全一致、可带辅助函数、不写 main；草稿不带编译器字段（判题用题目固定的编译器），语言一致性守卫对函数题跳过。
4. 已答题的处理由「已答题处理」三态决定：默认**跳过已答**；**仅重做错误题**只重做 PTA 判分未通过的编码题（含未提交草稿），已通过的题不再消耗模型 token；**全部重做**才覆盖所有已答题。**题干/选项含图的题默认跳过并在日志报告**——你用的是视觉模型时，可以打开「作答含图题」：插件会同你的登录态下载图片、编码后交给模型作答。该开关对**客观题与编码题（编程/函数）都生效**：编码题收题时按 DOM 顺序采集题干图片并记录每张图所属小节（题目描述 / 输入格式 / 输出格式），视觉 prompt 逐张标注后随文字题面一起交给模型；纯图片题（正文只有图片、没有文字题干）也按这条链路作答。未开开关时含图编码题直接跳过（不再按文字题面硬答——纯图片题那样只会产出与题意无关的代码并真实提交）。

## 运行中的中止与日志

- **运行中同一个按钮变为「中止答题」**，随时可叫停（含编码题批量作答的任意阶段）：在途请求立即断开、未开始的题目与题型不再作答、已填答案所在页照常保存（防「已填未存」被当作已答跳过）。
- 进度显示在悬浮球的进度环与面板日志里；日志可清空，每题请求前后实时记录（每题请求前记「请求模型中…」）、失败当场报告；编码题的收题与并发作答日志在当前页滚动，逐题提交阶段日志随各页出现、结束汇总带逐题失败明细。
- **日志跨页保留**：编码题逐题提交阶段每页都要整页装载，日志会写进当前标签页的 `sessionStorage`，新页面挂载时先回放整轮历史（上限 200 行）；「清空」会同时清掉持久化的日志。此前失败清单只在历史日志丢失时兜底回放。
- **LLM 请求有明确时限，且每次尝试都写日志**：OpenCode Go 经后台端口做**流式转发**，45 秒没有响应头、或 45 秒收不到任何数据就判定卡住（空闲错误最多重试一次）；**流式生成不再按固定总时长切断**——正文或推理增量会重置「300 秒无新内容」看门狗，推理模型连续思考数分钟也会等它跑完，你可以随时点「中止答题」；只有 SSE keep-alive、迟迟没有真正内容的流仍会在 300 秒判定卡住（网关忽略 `stream`、退回整段 JSON 的路径同理）。直连端点单次最多 120 秒、超时不重试。429 / 5xx / 网络错误 / 后台通道被回收最多尝试 3 次（指数退避 + 抖动）；400 / 401 / 403 这类配置或凭证错误不重试；扩展被重载/更新（`Extension context invalidated`）立即停手并提示刷新页面。流式生成会记录「模型已开始输出」、每 15 秒的已收字符数；推理模型还会记「模型思考中… 已收到 N 字符推理」，请求行带模型名。重试与最终失败都带尝试次数和总耗时——不会再出现几分钟全程静默、最后只剩一句报错的情况。
- **后台通道用端口而不是单条消息**：等待首块期间后台每 20 秒调一次轻量扩展 API 并回一条「仍在等待」进度，避免 MV3 worker 在 30 秒空闲时被回收（端口模式下挂起的 fetch 不算扩展活动，这正是 7-9/7-10 每条尝试约 30 秒断线的根因）；页面关闭或点「中止答题」会断开端口，后台连带取消在途生成。worker 若仍被回收，内容脚本会收到明确断开并按可重试错误处理，不再只剩一句 `message channel closed`。
- **运行期会临时压住 PTA 的离开确认**（切换题型的 `confirm` 与整页卸载的 `beforeunload` 原生框），避免续跑翻页被「离开此网站？」打断；运行结束恢复。万一页面被其他原因拦下、10 秒内没有跳转，插件会自动重试一次，仍失败则明确报错并停止本轮（不是静默停在待机）。

## PTA 访问频率限制

PTA 的「您访问得太快啦，不如休息一会儿吧」是**整页错误页**，限的主要是页面/文档访问；接口另有自己的限流（草稿写入两次至少隔 2.2 秒）。编码题批量模式按两类操作分别定节奏：

- **收题（SPA 切题）**：每次切题只发 4 个接口请求、不装载页面，每题之间固定等待约 2 秒（实测 1.2 秒连续切题也未触发限流，留了余量）；
- **提交（整页装载）**：每题回到题目页水合提交，每次整页装载前**固定等待 5 秒**（日志写明「等待 5s 再切换」）——旧逐题模式每题要装载两次仍会撞限流，批量模式收题不再装载页面，整页装载次数减半；
- 一旦在页面上识别到限流错误，暂停并回到续跑单里当前题的 URL 重试，冷却依次为 **60s → 120s → 180s**；三次仍被拒绝才停止（已完成的题目保持各自状态，不会重做）；
- 限流页不会被当成「收不到题目」继续翻页，也不会因为错误页换了地址而误判成你手动导航。

如果你手动操作时遇到这个错误：等几分钟再进入题目即可，不要连续快速点击下一题；批量作答进行中也不要手动切换题目，否则续跑会按「页面已离开本题」取消。

## 说明与限制

- DeepSeek 与「自定义」服务由页面上下文直连（端点需允许跨域）；**OpenCode Go 因网关不返回 CORS 头，改由扩展后台转发**，同样不经过第三方服务器，请求只发往 opencode.ai。模型回答质量由所选模型决定，作答是否正确需自行核对（客观题答题中 PTA 不提供对错反馈；编码题提交即评测，可用「仅重做错误」按判分结果重做）。
- **纯文本模型看不见图片**——含图题（客观题与编程/函数题）要么跳过，要么切到视觉模型并开启「作答含图题」；开启后编码题会把题干图片随题面交给模型，再按正常水合提交评测。图片经后台带登录态转成 data URL（图源 `images.ptausercontent.com` 不放行页面 fetch），不经过第三方服务器。OpenCode Go 各模型的图像输入能力官方未逐项标注，选用前请自行验证。
- **OpenCode Go 的用途边界**：官方文档说明该套餐面向 OpenCode 与其他 coding agent 类流量，并会监控滥用行为。用订阅额度作答客观题可能超出其预期用途，请自行评估；编程题相对接近其目标场景。
- **编码题（编程 / 函数）提交即评测**：自动作答会实时生成提交记录与作答度，成绩由评测结果（代码正确性与运行时限）决定，与客观题的静默判分路径不同（面板底部有同样的固定说明）。
